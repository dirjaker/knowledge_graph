# 知识图谱系统 — 完整项目规划

## 一、项目定位

一个**轻量级、本地化的知识图谱构建与可视化系统**。用户输入文本或文档，系统自动抽取实体和关系，构建知识图谱，并提供交互式可视化探索、自然语言查询、图谱分析等功能。

### 目标用户
- 研究人员：快速从文献中提取知识结构
- 学生：整理学习笔记中的概念关系
- 开发者：分析代码库/文档中的实体关系
- 任何需要从非结构化文本中挖掘知识结构的人

### 核心价值
1. **零门槛**：粘贴文本即可构建图谱，不需要懂查询语言
2. **AI驱动**：LLM自动抽取实体和关系，比规则精准
3. **交互探索**：点击、搜索、过滤、展开，像浏览地图一样探索知识
4. **本地运行**：数据不外传，SQLite存储，无需外部数据库

### 技术栈选型

| 层级 | 技术 | 理由 |
|------|------|------|
| **前端框架** | Vue3 (CDN引入) | 轻量，无需构建工具，适合单项目 |
| **图谱可视化** | D3.js force-directed | 最灵活，社区最大，力导向布局适合知识图谱 |
| **图表统计** | ECharts | 中文生态好，图表丰富 |
| **后端框架** | FastAPI | 已有基础，异步支持好 |
| **图存储** | SQLite + NetworkX | 轻量无依赖，NetworkX做内存图计算 |
| **LLM** | DeepSeek API + Ollama | 云端/本地双模式 |
| **文档解析** | pymupdf + python-docx | 已有基础 |

## 三、功能模块详细设计

### 模块1：文档导入与解析

#### 功能描述
用户通过三种方式导入数据，系统自动解析、抽取实体和关系、存入图谱。

#### 三种导入方式

**方式A：文本粘贴（主要方式）**
- 用户在大文本框中粘贴任意文本
- 点击"开始分析"按钮
- 系统调用LLM抽取实体和关系
- 展示抽取结果预览（实体列表 + 关系列表）
- 用户确认后导入图谱

**方式B：文件上传**
- 支持拖拽或点击上传
- 支持格式：TXT、Markdown、PDF、Word
- 自动解析文件内容
- 进入与方式A相同的分析流程

**方式C：手动添加**
- 表单方式逐个添加实体和关系
- 实体：名称、类型、描述、属性
- 关系：源实体（下拉选择）、目标实体（下拉选择）、关系类型、证据

#### LLM抽取Prompt设计

```
你是一个知识图谱实体和关系抽取专家。

请从以下文本中抽取实体和关系，返回JSON格式：

文本：
{text}

要求：
1. 实体类型包括：person(人物)、organization(组织)、location(地点)、
   concept(概念)、event(事件)、technology(技术)、product(产品)
2. 关系类型：works_at、located_in、part_of、created、uses、
   founded、invested_in、related_to、mentioned_in
3. 每个实体需要：name、type、description
4. 每个关系需要：source、target、type、evidence
5. 只抽取文本中明确提到的实体和关系，不要推测

返回JSON格式：
{
  "entities": [
    {"name": "...", "type": "...", "description": "..."}
  ],
  "relations": [
    {"source": "...", "target": "...", "type": "...", "evidence": "..."}
  ]
}
```

#### 图谱可视化详细设计

**节点设计：**
- 圆形节点，大小根据连接度动态调整（最小20px，最大60px）
- 颜色按实体类型分配（8种类型，8种颜色）：
  - 人物(person): #E91E63 (粉红)
  - 组织(organization): #2196F3 (蓝)
  - 地点(location): #4CAF50 (绿)
  - 概念(concept): #9C27B0 (紫)
  - 事件(event): #FF9800 (橙)
  - 技术(technology): #00BCD4 (青)
  - 产品(product): #795548 (棕)
  - 其他(other): #607D8B (灰)
- 节点内显示实体名称（最多4个字，超出截断+省略号）
- 悬停时显示完整名称 + 类型 + 描述（tooltip）

**边设计：**
- 曲线连接（避免重叠），带箭头方向
- 颜色：半透明灰色 rgba(150,150,150,0.4)
- 粗细：根据weight属性（1-5px）
- 边上显示关系类型标签（小字，可开关）
- 悬停时高亮边 + 显示证据文本

**交互设计：**
1. **点击节点**：右侧详情面板展开，显示该节点完整信息和所有关系
2. **双击节点**：展开该节点的1跳邻居（懒加载）
3. **右键节点**：上下文菜单（展开邻居/查看路径/固定位置/删除）
4. **点击边**：显示关系详情（类型、权重、证据）
5. **拖拽节点**：调整位置，松手后固定
6. **滚轮缩放**：缩放画布
7. **拖拽画布**：平移视图
8. **框选**：按住Shift拖拽可多选节点

**搜索与过滤：**
- 顶部搜索框：输入关键词实时匹配节点名称
  - 匹配的节点高亮，其他节点变暗
  - 回车或点击搜索结果定位到该节点并居中
- 类型过滤：下拉多选框，取消勾选的类型对应的节点隐藏
- 布局切换：力导向 / 环形 / 层级 / 网格

### 模块3：智能查询

#### 查询方式

**方式A：自然语言问答**
- 底部输入框，类似聊天界面
- 支持的问题类型：
  - 实体查询："张三是什么职位？"
  - 关系查询："张三和李四什么关系？"
  - 路径查询："张三和王五之间有什么联系？"
  - 邻居查询："张三认识哪些人？"
  - 搜索查询："哪些公司使用Python？"
- LLM理解意图 → 生成查询 → 执行 → 返回结果
- 结果同时展示文字回答 + 图谱高亮

**方式B：结构化查询**
- 表单式查询界面
- 选择查询类型 → 填写参数 → 执行
- 查询类型：
  - 查找实体：按名称/类型/属性搜索
  - 查找关系：指定两个实体，查找它们的关系
  - 路径查找：指定起点和终点，查找路径
  - 邻居查询：指定实体，查找N跳邻居
  - 模式匹配：S-P-O三元组模式匹配

### 模块4：图谱分析

#### 分析功能

**4.1 统计概览**
- 仪表盘页面，展示图谱整体信息
- 指标卡片：实体总数、关系总数、文档数、平均度数
- 图表：
  - 实体类型分布（饼图）
  - 关系类型分布（柱状图）
  - 度分布（直方图）
  - 连通分量数量

**4.2 中心性分析**
- 度中心性 Top10（连接最多的节点）
- 介数中心性 Top10（最重要的桥梁节点）
- 接近中心性 Top10（最中心的节点）
- PageRank Top10（最重要的节点）
- 结果以表格+柱状图展示，点击节点可定位到图谱

**4.3 社区发现**
- Louvain算法检测社区
- 结果展示：社区数量、每个社区的节点列表
- 在图谱上用不同颜色标记不同社区

**4.4 路径分析**
- 选择两个节点，查找所有路径
- 最短路径高亮显示
- 路径列表，点击可在图谱上展示

## 十、关键设计决策

1. **前端不用构建工具**：Vue3 + D3.js 全部CDN引入，单HTML文件，降低部署复杂度
2. **LLM抽取为主，规则为辅**：LLM抽取精度远高于规则，规则作为fallback
3. **SQLite不换Neo4j**：轻量部署，无需额外安装，对中小规模图谱足够
4. **Canvas不选SVG**：节点超过500个时SVG性能急剧下降，Canvas更适合
5. **力导向布局为主**：最适合知识图谱的探索式浏览
6. **异步处理LLM请求**：大文本抽取可能耗时较长，用任务队列异步处理
